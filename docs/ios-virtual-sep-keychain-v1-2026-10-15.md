# HuntMob virtual SEP v1 — macOS root storage

This helper stores an experimental HuntMob identity root for each VM. It does
not reproduce an Apple UID, a physical Secure Enclave, hardware attestation, or
Apple's derivation algorithm. It does not make the native iOS runtime ready.

## Build and API

Source: `components/ios-storage-crypto/virtual_sep_keychain.c`.
Build without third-party packages:

```sh
python3 scripts/build_virtual_sep_keychain.py --output /absolute/new/helper/path --self-test
```

The destination must be new. The build links only Security.framework and
CoreFoundation.framework and returns source/binary hashes as public metadata.
Keep the selected helper path and code identity stable for existing items;
Keychain ACL access must fail closed if a replacement helper is not trusted.

Supported operations:

```text
helper --create <canonical-lowercase-VM-UUID> --output-fd <inherited-write-pipe-fd>
helper --lookup <canonical-lowercase-VM-UUID> --output-fd <inherited-write-pipe-fd>
helper --self-test
```

The caller supplies a dedicated inherited pipe, separate from stdin/stdout/
stderr, and reads exactly 32 bytes followed by EOF. Descriptor numbers below 3,
read-only descriptors, terminals, non-pipes, and descriptors aliasing standard
streams are rejected before item creation. Regular files cannot receive roots.
The caller must validate process exit status and the JSON receipt as well as
the pipe byte count. A failed operation supplies no root; a partially failed
delivery must never trigger a substitute key or plaintext I/O.

Stdout contains one JSON object with action, public VM UUID, model version,
service, result, and creation/delivery booleans. Root bytes, root digests, and
passwords are absent from stdout, stderr, arguments, and explicit disk files.
Do not log the inherited pipe or copy its bytes into a CLI argument/file.

## Storage and failures

The item is a generic password in the macOS default **file-based Keychain**:

- Service: `HuntMob.VirtualSEP.v1`.
- Account: the exact canonical VM UUID.
- Value: 32 bytes generated by `SecRandomCopyBytes`.

Creation uses `SecItemAdd` and never replaces an existing item. Duplicate
creation fails; lookup must be requested explicitly. Lookup of a missing item
fails without creating a root. A successfully added item remains present if
delivery fails, permitting a subsequent explicit lookup.

Both adding and lookup are bound to the same default Keychain rather than an
unrestricted Keychain search list. The helper disables Keychain interaction
and requests authentication UI failure. A locked Keychain or required approval
must produce an error; there is no prompt, password argument, fixed key, random
replacement on lookup, or plaintext fallback. Locked-Keychain behavior is not
claimed as dynamically tested: the implementation uses the documented policy
without locking or changing the user's Keychain.

This is a CLI-compatible file-based Keychain item, not the data protection
Keychain and not a Secure Enclave non-exportable key. Apple distinguishes these
implementations and their ACL/provisioning requirements in
[TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains).
The no-prompt policy follows
[SecKeychainSetUserInteractionAllowed](https://developer.apple.com/documentation/security/seckeychainsetuserinteractionallowed(_:))
and [kSecUseAuthenticationUIFail](https://developer.apple.com/documentation/security/ksecuseauthenticationuifail).

The process disables core dumps and clears its own root buffers with volatile
writes. Security/CoreFoundation-managed internal copies are released through
their APIs; this does not claim erasure of every OS/internal copy or register.
There is no generic delete or migration operation in this helper. The launcher
owns the public VM manifest and must require explicit provisioning of a new
identity before any native candidate is associated with this root.

## Bounded self-test

`--self-test` generates fresh UUIDs internally and creates only its own fixture
items. It verifies pipe delivery, lookup in a new helper process, distinct roots
for distinct VMs, duplicate-create preservation, missing lookup, and invalid
descriptors without item creation. Comparisons occur in memory; receipts
contain booleans, never roots or root hashes.

Cleanup uses `SecItemDelete` only for UUIDs internally generated and confirmed
created by that invocation. There is no user-controlled cleanup account or
general deletion flag. Failure to clean up makes the test fail. No iOS image,
existing VM identity, backing disk, engine configuration, or user Keychain item
is modified by the tests.
